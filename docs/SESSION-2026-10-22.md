One Claude Code session, about 28.5 hours of wall clock, rebuilt the engine: the game now runs on
the new core (`src/core/`: the state as plain data, `step(state, command)`), the old engine is
gone, and a first wave of gameplay bugs is fixed. This report records what was done, what went
wrong and what waits for a decision. The plan behind it is docs/REFACTOR.md step 4.

## What was done

1. **Survey and cleanup.** A code review found 6 bugs (#110-#115); `/simplify` with 4 reviewers
   merged duplicated code into helpers and fixed stale comments (#122).
2. **The design**, in a few rounds with the owner: two tracks (rules, players), then the goal of
   the state as data, a new core built beside the old engine, the gameplay frozen while it was
   built, the new UI as a stage of its own. The key decision: parity means the same gameplay, not
   the same code. Written down in docs/REFACTOR.md, docs/STATE.md and docs/CORE.md.
3. **Stage A, the groundwork.** One command entry for every player action (#119); property-based
   tests with fast-check (#125), which found 3 bugs at once.
4. **Stage B, the verification switch.** Separate random streams for the game, the AI and the
   cosmetics (#126); `toData` and `fromData` (#127); a lossless, versioned save (#128), which fixed
   9 data-loss bugs.
5. **Stage C, the new core beside the old engine**, each layer proven equal to the old engine by
   differential tests:
    - C1, state and queries: the move range 1.1-2.3x faster.
    - C2, commands: a move 3-7x faster, an attack 2-3x.
    - C3, the turn, a new game from a scenario file (all 403 scenarios agree) and campaigns (all 17
      agree).
    - C4, the AI and the tutorial as controllers: an AI turn 1.3-3.2x faster.
    - C5, the game switched to the core and the old engine removed (#190-#199); then a performance
      fix brought the screen's queries back from hundreds of µs to 1-17 µs (#200).
6. **The first wave of fixes, the gameplay freeze over.**
    - Movement: #70 (the start hex's cost), #167 (an entry cost of 0), #69 (column 0), #205 (the
      PG2 rule from the manual: a hex is entered only with the points and fuel to pay for it).
    - The AI: #74 (stacking on its own units), #171 (undoing a retreat), #207, #75 (the fog of
      war), #82 (transports, waiting to merge), the crashes #100 and #101.
    - The UI: #186 and #187 (the UI wrote the game's state), #208, #111, #79 and #86 (the combat log).
    - The spotting counters' drift, #72 and #73.
7. **Process and tools.** The flaky verify script fixed (#139); verify made a required check, with
   the label `behavior-change` as the audit trail of a deliberate change; a new push clears the
   label; no `git stash` in worktrees.
